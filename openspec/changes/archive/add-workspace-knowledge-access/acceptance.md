# Acceptance

本文件固定 Goal 达成条件。OpenSpec 格式通过、测试通过、容器健康和模型 HTTP 200 各自只能证明局部，不能代替下面的完整验收。

## A. 必须交付的结果

1. 两个真实运行且固定为 air／water 的独立 LightRAG 实例，连到共享 PG／Qdrant／Neo4j；一个可信 Knowledge API 和可使用网页；客户端没有未认证内部旁路。
2. 冻结分类清单中的 air／water 逻辑文档全部导入或有内容／身份依据的 duplicate 记录；分片覆盖得到证明，两库目录／搜索索引 active 且 current。未解释失败、缺失必要分片或未导入项均使全量条件不通过。
3. 四类主体（大气、水、双库、无权）的真实授权行为符合矩阵；每种资料读取接口执行当前权限，越权读取为零。
4. PG 单库／双库、LightRAG 原生模式及 PG 组合真实可用，答案使用本次合法证据；完整范围、版本和引用合同保留。
5. 同一真实资料可以在两库存在，构建和读取不冲突；同库重复入库幂等，中断可恢复，重启不丢授权／索引／记录边界；更新只影响目标库。
6. 新增第三个 workspace 只需注册配置、启动／入库和角色授权，无核心检索代码改动；真实小样本验证后可安全清理试验数据。
7. 旧 default、非本轮空间、源资料、gold、`.env` 和历史证据保持原身份；本轮成果可启动、可恢复、可回滚并本地提交。

以上 7 条和下面矩阵全部通过才能说“Goal 达成”。外部阻碍不能当成功；阻碍报告可作为停止实发的依据，但不是验收完成。

## B. 主体与知识库矩阵

|主体|请求 air|请求 water|请求 air+water|all|既有 default|
|---|---|---|---|---|---|
|大气读者|允许|拒绝|整体拒绝|只展开 air|拒绝|
|水资料读者|拒绝|允许|整体拒绝|只展开 water|拒绝|
|双库读者|允许|允许|允许|air+water|拒绝|
|无知识库授权主体|拒绝|拒绝|拒绝|拒绝|拒绝|
|未认证／伪造凭据|拒绝|拒绝|拒绝|拒绝|拒绝|

未知 workspace 拒绝；伪造 role／enterprise／workspace 参数不增加权限。相同角色名在不同企业不能继承另一企业的 grant。明确拒绝整个混合请求，不能“自动挑其中有权的库”冒充满足原请求。

每个拒绝场景核对：检索／LLM／embedding／rerank 没有因此发起、来源文件未读、响应没有受限文档名称／内容／计数或其它库存在性。认证错误可返回 401；已知授权错误 403；对象 ID 不存在／不可访问可统一 404，不泄漏存在性。

## C. 全部读取端点

实施者列出实际路由及测试用例 ID，至少覆盖：查询、澄清后的查询、生成旧记录、record 列表／详情、结果导出、chunk／文档引用、PDF、解析正文、图谱／证据展示、缓存命中和重启恢复。

- 大气主体持有合法水记录／chunk／文档 ID／来源 URL 仍不能读；反向同样执行。
- 两主体即使共享 workspace，不能读对方的私有记录；企业参数不能转换记录所有者。
- 双库记录在主体被撤销 water 权限后必须拒绝读取／生成／下载，不部分泄漏原记录。
- 同问题、同参数在不同角色下不会命中另一主体的答案／记录；授权代次、workspace 快照变化使旧缓存失效。
- 登录退出／切换身份、切换知识库、慢请求返回、页面刷新及服务重启都不能重现无权内容。浏览器已经下载到用户设备的数据不在撤销回收范围，本轮不宣称远程删除已有副本。
- 未携内部实例凭据不能直接访问 LightRAG 查询／图谱／文件／管理接口；读者凭据不能入库／删除／修改配置。使用不会破坏已有数据的拒绝请求验收。

## D. 数据、来源和重复

|检查|现场证据|
|---|---|
|清单冻结|每份源文件 SHA、分类依据、逻辑文档／分片映射、目标库、排除／duplicate 依据|
|全量完成|逐项终态、实际 docs／chunks／图谱／向量身份、有效向量维度、目录／索引 active 身份；分母与清单一致|
|来源隔离|air 的输出只引用其登记资料／显式共用资料，water 同理；实体描述／边来源不得残留未授权另一库引用|
|跨库重复|同一真实资料在 air／water 均可独立读；同 ID 不覆盖，snapshot/search 构建无全局键冲突，副本来源均保留|
|同库幂等|再次执行同清单新增行 0、无不必要模型调用；已有 duplicate 能定位到成功内容|
|恢复|在已持久 checkpoint 后模拟中断，再继续剩余项；不重跑已确认完成请求，不改旧库；实发但结果未落盘的 uncertain 边界单独验证和记录，不假称模型 exactly-once|
|增量|本轮试验资料更新／撤回使目标库及其缓存／派生索引准确更新，另一库身份和查询保持|
|第三库|一份真实资料通过仅配置扩展可查，未授权主体拒绝；记录核心代码无变更|
|保护|旧 workspace 的原文／状态／图谱／向量与 active 派生身份对照一致，源文件／gold／历史文件／`.env` 哈希一致|

不要求新图谱逐字复现旧图谱；要求每个返回来源实际存在且属于授权范围。不能用合成数据库 fixture 冒充真实入库，允许离线 fixture 单独用于错误／同 ID／中断边界测试。

## E. 真实检索与模型

在小样本后、正式现场验收前固定问题与独立期望，从源文档核对标准、版本、表／条款和来源。

1. air 和 water 各至少 3 个 PG 真实任务：文件清单、正文条款、已确认逻辑表；覆盖 top-k 不截断已确认范围。若所选表／条款先验结构不完整，换用完整范围必须发生在冻结前；冻结后失败保留并修实现，不换题凑成功。
2. 两库分别对 naive／local／global／hybrid／mix 及其 PG 组合至少一次有界功能验证：确认真实模式 dispatch、所属实例、原始 chunks／实体／边／引用和失败可见性。可明确复用同次合法检索记录供组合，但标 reused，不称独立 fresh。
3. 双库主体至少一次跨库问题，分别取得两个 workspace 的合法证据再合并、最多一次生成；展示每库来源与状态，不能把两份已经生成的答案拼起来。
4. 用当前 DeepSeek 模型至少完成 air、water 和双库问题各一次真实生成；记录实发请求模型、返回模型／usage（缺失就标 unavailable）、证据哈希和结果。模型需要有证据支持并能区分知识库，不以 200／非空回答当正确。
5. 真实 embedding 返回 2560 维并写入正确新 workspace；reranker 只在实际启用时核验，同一次路线不静默更换排序配置。没有用 rerank 的路线明确关闭，不伪报调用。
6. 至少一项服务失败／stale／缺文档控制；明确未就绪／部分结果，不能回退 default、隐藏某库失败、把不完整范围标 complete。

此为权限与功能验收，不要求本轮重新证明融合优于 local，也不承诺任意开放问题正确。失败请求计入本轮调用账本，历史答案不作为现场模型结果。

## F. 实际浏览器

实际启动网关网页并操作，至少留下桌面和窄屏截图及操作记录：

- 大气／水／双库／无权主体登录，授权知识库选项正确；一次退出和身份切换。
- 单库、双库查询；普通问答与对照选择不额外发请求；切换库不调用模型并正确隔离旧结果／澄清上下文。
- 检索后生成、引用展开和正确 PDF／解析文本读取；导出与历史记录只看到当前主体合法数据。
- 页面无权／库未就绪／stale／后端失败状态，以及窄屏／键盘基本操作。
- 在浏览器外以原始 HTTP 请求完成越权参数、record ID 和下载 URL 测试；仅“网页隐藏选项”不算权限验收。

自动化可承担浏览器操作，但 DOM 静态检查和截图生成脚本不能冒充实际页面运行。截图不含凭据。
