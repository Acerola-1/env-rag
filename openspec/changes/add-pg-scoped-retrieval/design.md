## Goals / Non-Goals

**Goals:**

- 先形成能审查的事实合同，再实现 PG 第二路；从真实语料完整取证，输出可回溯到 chunk 和原始 block／table 的结果。
- 保持原文单一来源，新增目录和派生索引可重建；不跨 workspace、文档或快照混读。
- 用同样的样本和生成条件判断 PG 单路及融合的增益，保留每个阶段失败或部分完成的事实。

**Non-Goals:**

- 本次计划编写不执行入库、迁移、模型推理或功能实现。
- 不修改 LightRAG 源码或既有表，不重新解析 PDF，不重新做全库 embedding，不新增 ES。
- 不实现通用 Text-to-SQL，不承诺全量生产规模，不把库内文件清单称作全部现行标准。
- 不在本阶段自动修复 58 条 failed 状态或删除缺失／异常资料。

## Decisions

### 1. 先只读审计，形成阶段门槛

第 0 阶段允许在本工程编写可复跑审计脚本，读取现有数据，保存脱敏报告；连接使用只读事务与超时。不得实例化可能自动建表／迁移的存储组件并指向现有库。

首次交付目录：`reports/pg-retrieval/phase-0/`，包含：

- `audit.md`：结论、方法、统计、异常和建议。
- `inventory.jsonl`：每份产物及 PG 文档的对应结果，含 workspace、实际 doc ID、路径、原始哈希及其语义、状态、chunk 数、解析文件可用性、快照指纹。
- `schema.json`：PG 版本、相关表字段／索引、文本搜索配置、脱敏运行配置和依赖版本。
- `mapping-samples.jsonl`：代表性正文 block 和物理表片段到 chunks 的映射，含完整／部分／未匹配状态及依据。
- `compatibility.md`：发布包公开接口、返回证据字段、workspace／集合命名与兼容性问题；首轮优先离线检查，未实际连接的路径明确未验证。
- `search-probes.json`：默认中文词项问题、标题与正文查询示例、拟采用应用分词的探针方案；不得声称尚未安装的方案已通过。
- `sample-set.json`：固定真实文档及问题白名单，标注正例、缺失／歧义例和标准答案依据；覆盖文件、正文、表格、单点事实和跨文档比较。
- `run-manifest.json`：时间、代码版本、执行方式、输入指纹、查询范围和失败步骤，避免凭一份无来源的结论推进。

所有计数区分“目录数、唯一身份数、processed 文档数、有 chunks 文档数、实际可读数”。对不一致保留解释或未解问题，不靠重新导入消除证据。

**Gate 0：**主 agent 审查报告，确认白名单、映射依据、语料排除项和兼容性风险已明确，才能实施辅助表。此门槛是技术审查，不要求每个常规实现选择都再向用户确认。若公开接口不兼容，保留 PG 独立路线；融合阶段等待修订兼容方案，不能自动升级依赖或迁移现有库。

### 2. 自有 schema 管理派生数据

计划使用 `env_rag` schema，阶段 0 先确认名称未被其他应用占用；占用时选择明确的应用隔离名。原有 `public.lightrag_*` 只读，迁移只操作本应用拥有的对象。

建议对象：

| 对象 | 最小字段／作用 |
|---|---|
| corpus_runs | 构建版本、输入指纹、词表／分词版本、完成状态、活动快照 |
| documents | workspace、doc_id、snapshot_id、原始路径、自身编号／版本、标题／类型／日期、字段来源与置信度 |
| source_units | 原始 block／table ID、顺序、章节路径、页码与 locator；只保存定位信息 |
| unit_chunk_links | unit 与 chunk 多对多映射、覆盖状态、匹配依据、片段跨度 |
| scopes / scope_units | 完整章节／条款／逻辑表格及其有序成员，确认状态和覆盖状态 |
| search_documents / search_chunks | 清洗后搜索视图、tsvector、对应 chunk ID、搜索配置版本 |

精确身份使用 `(workspace, doc_id, snapshot_id)`；chunk 身份至少包含 workspace 与实际 ID。逻辑表身份还包含章节／附录及表号，不以“表 1”全库唯一。数据结构允许一个 block 跨多个 chunks，一个 chunk 承载多个 blocks／tables。

派生索引的构建流程为：读取固定来源快照 → 校验映射 → 在新 build 中写入目录和搜索视图 → 核验引用 → 原子切换活动 build。重复相同输入幂等；不完整 build 不可成为活动版本。查询比较来源指纹，变化时报告 stale 并要求重建，不沿用旧定位。旧原文没有历史快照时，不能只保存旧目录就宣称可以读取历史原文。

元数据先提取自身编号、标题、版本年份、类型与可验证日期。发布／实施／报告统计期分开；正文引用的标准号记录为 referenced_codes。未知值保留 unknown，低置信主题标签优先软加权，不硬排除。

### 3. 结构映射先行，全文排名随后

先实现纯 SQL 文件定位和有序读取。映射优先使用现有 sidecar.refs、HTML table ID、MinerU 的 block／table ID；缺失时使用有依据的局部内容对应，模糊匹配不能自动升级为 confirmed。

章节边界由有序原始 blocks 的标题路径与条款标识确定，不能只靠 chunk.heading；原始产物本身标题异常时保留原值与审查状态。用 source units 保留精确范围，chunk 用于取原文与融合引用。范围落在大 chunk 的局部时，使用可验证跨度或对应原始单元提取，避免把邻近无关内容算入枚举。

逻辑续表结合文档、章节、表号、caption、顺序、表头及序号核验。序号连续只是辅助证据，关联不明确返回 partial／ambiguous。使用 lxml 读取已有 HTML，处理 rowspan／colspan、重复表头、注释和单位；原始 HTML 与 locator 不变。

**Gate 1：**真实白名单的表格、正文、文件枚举均能完整取证并引用；缺片、跨章节同表号、跨 workspace、来源变更等反例能明确拒绝或报告部分结果，才能进入全文候选调优。

### 4. 中文全文检索采用应用侧分词基线

应用侧分词输出分隔词项，PG 使用 `simple` 构建 tsvector＋GIN，并以 `ts_rank_cd` 为初始排序。优先探针 jieba＋受控环保词表，确认安装版本后用 uv 锁定；如探针失败，先修正词表／查询构造并记录原因。分词器、词表、清洗、编号规范化均版本化，索引与查询必须一致，保留词项位置供覆盖密度排序使用。

标题、caption、heading、正文分配权重；HTML 先提取可搜索文本，剔除标签与噪声。标准编号单独做 Unicode、空白、连字符规范化与精确查找，不依赖中文分词。自然语言问题先提取关键概念和限制条件，不能直接把“有哪些、请列出”等词全部用 AND 连接。先查询核心词组合，再做有记录的受控 OR／同义词放宽；不改变用户指定版本。

编号定位 → 元数据限定 → 关键词候选 → 范围确认 → 全部范围读取。候选阶段可以 top-k；完整范围阶段使用稳定分页／流式读取，不能受候选 top-k 截断。全文索引和辅助查询 B-tree 全部建在自有 schema；通过 EXPLAIN 和实际延迟验证，不向原始 LightRAG 表直接添加索引。

默认 PG 中文处理已实际失配，因此不选择“直接 to_tsvector 原文”的捷径。暂不引入数据库中文扩展以降低服务镜像耦合；暂不引入 ES，以真实证据判断是否需要换候选引擎。

**Gate 2：**固定词汇探针正确，PG 候选证据 recall@20 ≥ 0.90，明确编号／版本查询正确率 100%；若不达标，公开失败案例，调优第二路，不能用后续精排掩盖未召回问题。20 为初始评测预算，变更预算需要同步评测合同。

### 5. 统一检索输出与完整性语义

三个枚举闭环：

- 文件枚举：读取全部明确匹配的目录项，输出库内范围、匹配谓词、分页计数与未知元数据排除项；“读完匹配结果”不等于主题标签找齐所有相关文件。
- 正文枚举：确认章节／条款范围，读全有序原文，模型分批抽取 items＋引用；合并去重时保留原始项，自动核验引用确实包含主张。
- 表格枚举：确定列和逻辑表全部片段，程序提取行列；复杂列选择可由模型辅助，但不补造缺失行。
- 跨文档枚举／比较：每个目标文档独立覆盖，再合并；缺少一个版本时明确 incomplete，不用近似文档替代。

输出至少包含 query_id、workspace、snapshot_id、scope_ids、候选路径与分数、evidence、items、coverage_status、warnings；条目关联实际 unit／chunk IDs 和原文引句。状态使用 complete／partial／ambiguous／stale。complete 只表示已经验证的目标范围覆盖，不承诺解析器未漏掉原 PDF 的内容。

范围太长时分批读取／抽取，累计处理单元和引用。超时或预算不足返回 partial 与已处理／总量，不能静默截断后宣称列全。

### 6. 融合从公开接口适配开始

`LightRAG local 候选 + PG 候选 → workspace/chunk ID 去重 → 联合 rerank → 选择目标范围 → 完整展开 → 抽取／生成`。

单点事实可选少量证据；枚举以 scope 为保留单元，选中后保留全部必要成员。LightRAG 已有 rerank 不可代替合并后的联合精排；原始检索分数不可直接相加。发布包必须能提供本次候选的实际 chunk IDs、内容和来源，适配器不能根据显示 reference 编号猜 chunk 身份。

首次接入优先使用确认兼容的只读证据接口；任何 initialize_storages 或 schema migration 的副作用必须先在隔离临时库或测试 workspace 证明，再确定正式接入。必要时调整调用入口，不能为适配发布包重写已有存储。

PG 定位的强编号／版本条件也约束 LightRAG 候选。版本对比显式允许各目标版本并分别保留范围，不因去重丢掉版本来源。reranker 失败、超时、分数异常分别记录；允许显式降级，但结果与评测标注 degraded，不计作精排成功。

**Gate 3：**身份／版本一致、联合精排实际发生、完整范围无截断、失败状态可见，之后进行正式对照。

### 7. 评测先冻结样本与答案

第 0 阶段提出样本，主 agent 审查后固定至少 30 道真实题：fact、文件 enum、正文 enum、表格 enum、synthesis 各至少 6 道；另加至少 8 个反例验证异常行为。只从明确白名单选题，不能为了通过更换困难样本；编号／范围有歧义题另行标记，不混入正例命中率。

每道题保存文档与来源快照、目标范围、标准项目集合或事实断言、原文引用和答案审核状态；无审核的答案不计入质量指标。难例包括同名不同年份、引用别的标准号、正文跨 chunks、跨页续表、超出一页的文件清单、缺一个版本、长范围超时。

比较 LightRAG local、PG 独立路径、两路融合；mix 仅作可选参考。模型、reranker、提示词、候选预算和输入语料冻结，同一轮记录全部配置；至少两轮冷生成，分别报告检索／精排／展开／生成延迟和端到端 p50／p95。禁止复用答案文件或答案缓存；使用同一次生成的实际上下文，不能另调一次查询拼上下文。

验收最低标准：

| 指标 | 门槛／报告方式 |
|---|---|
| 已确认文档身份／编号／版本定位 | 白名单正例 100% 正确，所有 unknown 明确 |
| 已确认范围覆盖 | 正例 100% 范围单元被读取；全部反例无 false complete |
| PG 候选证据 recall@20 | ≥ 0.90，记录漏掉的真实来源 |
| 三类 enum 集合完全正确率 | 各类别 ≥ 5/6；所有条目来源可验证，不只报平均分 |
| 引用、跨 workspace／版本混入 | 引用错误及违规混入为 0；缺失结果不得伪造 |
| 融合增益 | 两轮 enum 完全正确率均不低于 local；至少一类存在可复现修复案例；fact／synthesis 正确率均不得下降 |
| 延迟与降级 | 报告分阶段 p50／p95、样本量和降级次数；无历史 SLO，不承诺固定秒数；默认第二路并行、明确编号可直达 PG，避免无意义多次推理 |

小样本指标是初版验收门槛，不构成生产规模或稳定统计优势。Gate 4 未达标时保留失败报告，默认路径维持已验证基线，不强行启用融合。

## Risks / Trade-offs

- [标题、编号、日期抽取错误] → 字段附来源／置信度，允许 unknown，区别自身编号与引用编号。
- [chunk 含多章节或表格被切开] → unit-chunk 多对多＋精确范围证据；确认不了则 partial，不靠标题猜测。
- [索引期间来源变化] → 指纹前后核验，构建原子发布，查询检测 stale；必要时只处理冻结白名单。
- [PG 原生排名对中文关键词效果不足] → 固定词表和查询合同做真实召回探针，先调优，再以报告决定是否另提引擎变更。
- [发布包接口与定制存储不兼容] → 隔离兼容探针，保持 PG 里程碑独立；融合不越过迁移边界。
- [枚举范围过长导致推理成本上升] → 程序提取表格、分批正文、明确预算与 partial；不以截断冒充完整。
- [小样本误判收益] → 按类别报告两轮结果和失败题，禁止把阶段验收推广为全库或生产能力。

## Migration Plan

1. 本次仅生成并验证计划文件。
2. 执行第 0 阶段只读审计，在 Gate 0 后冻结数据合同与白名单。
3. 实现显式辅助 schema 迁移和构建，测试数据使用独立 schema／workspace；构建前展示操作对象。
4. 按 Gate 1、2、3、4 推进，失败停在该阶段并输出证据，独立工作仍可继续。
5. 回退通过配置关闭新路径或重建已验证配方的辅助目录。当前目录保留活动snapshot，旧目录行随原子发布修剪、retired账本保留；不能直接切回已删除目录。只清理本应用明确拥有的辅助对象，保留现有LightRAG表、原始解析产物和失败报告。关闭路径后原服务行为保持可用。

## Open Questions

- 合理延迟预算是多少？先测两轮分阶段数据，再由主 agent 提出默认预算，不能虚构尚未存在的 SLO。
- 222／221 的具体差异原因与失败资料的后续处置？第 0 阶段查明事实；缺失资料修复单独处理，不阻断明确有效白名单的验证。
