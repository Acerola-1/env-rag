# 下一组：Phase4 零请求评分准备

## 目标与授权边界

收尾离线材料已通过，主 agent 勘误见 phase-4-finalization-offline-review/review.md。**先让新运行能够被可靠评分，再决定正式付费两轮。** 本组允许在全新 `reports/pg-retrieval/phase-4-scoring-readiness/` 实施评分工具适配、测试与说明，不改生产源码、提示、gold、.env、配置锚、任何历史工件/冻结测试，不跑真实服务/数据库/模型/健康探测，不启动123/246腿。

无需回头重写离线交付；把勘误引用进新代。编辑前捕获输入工具/冻结/当前来源锚 SHA；输出目录固定为全新目录，禁止脚本默认写回历史路径。Python 导入/测试设 PYTHONDONTWRITEBYTECODE=1，避免受保护 pyc 漂移。

## 实施面一：评分工具绑定运行代次

以已验收 assessment-r3/assess_round1.py 为只读基线，在新目录复制适配。保留集合投影、条款号与全文跨度、身份/文件名、反例行为、决定性失败优先、分母不缩与掩码 pending 规则。旧 SHA 不匹配拒绝是正确行为，不能加无条件豁免。

显式配置 run_dir、approved_anchor 和独立 output_dir；人工记录与映射清单可以是明确附件路径，不为追求“只有两个参数”而隐式寻找旧答案。新代输入合同必须绑定：运行目录与每题工件 manifest、该轮批准代码谱系、固定 gold、真实完整 pre/post 身份。不同代码谱系用明确新锚；锚不得在验证时回写当前值。局部测试使用临时锚与 fake 输入，绝不改真实锚。

一个两轮运行按实际 round 标识读取，逐轮各123行（93正例+30反例），不把 r1 路径硬套到第二轮；逐路径分母保持。缺 manifest、错误 SHA、结构/解析异常、身份不齐/漂移统一写净化拒绝诊断并非零退出，不产裁决文件。空输出目录是必须条件；不读旧 answer 字段冒充新输出。

## 实施面二：规则与人工观察分离

旧 `_MANUAL` 21 条只能在明确的受保护 Round1 兼容模式使用；其历史调用表述不用于账本推断。新代人工记录至少绑定 run/round/qid/path、answer runtime SHA、审查者、verdict、理由、已检查项；有真实模型响应/上下文时另绑对应 SHA，缺响应明确 absent。

- 同题同路径的新输出 SHA 不同：旧 FAIL/PASS 都不得继承。无适用记录时需人工的项为 PENDING；机械决定性 FAIL 保持 FAIL。
- 支持人工 PASS/FAIL/PENDING 输入，但 PASS 仅能解决记录明确审核的语义/载体缺口；不得覆盖身份、引用、数值支持、集合、覆盖等已经证实的失败，也不得把 raw 模型正确而应用没有交付算完成。
- fact 散文载体不因格式自动错/自动对；人工按题目要求的主体、值、单位、时间/等级及逐字来源裁决。附录 A 与规范正文分列，不改 gold/容许范围。
- HTTP实发由本题真实 call 凭证判定。incomplete_answer_coverage 可在成功 HTTP 后发生，不等于未发；unknown 不猜零。预留与实发始终分列。

先用**合成输入和已存工件副本**证明上述通道，不能预造未来运行的人工作答结论。旧22项待审清单订正为12fact+3file004+3neg002+1neg005/local+3neg008；不改其历史终判。

## 实施面三：映射采集设计与无请求接口

本组只写接口/格式与 fixture，**不执行采集**。映射实际依据 env_rag.unit_chunk_links JOIN source_units（组合键workspace/doc_id/snapshot/unit_id），scope关系按scope_units/scopes；public.lightrag_doc_chunks可另核验来源，不能单独造unit对应。

给出只读一次采集的确切分页、数据SQL上限与失败语义提案（原≤20需证明够用，守卫单列）；完整映射/来源指纹/目录快照/内容SHA写入独立manifest。missing映射明确pending，不能空表当完整，跨workspace/快照引用拒绝。评分只用展开前discovery与typed目标，映射提供关联证据不证明读完整scope；展开/精排/枚举答案永不反灌召回。

若本组不实现typed评分，明确接口未实现和pending即可，不扩大为新检索算法；实现则保留原typed目标口径并交付已知映射/缺映射的正负例。

## 必验矩阵

35项两轮历史冻结测试字节不动，使用 ENV_RAG_ASSESSMENT_SCRIPT 指向新副本，在显式旧代兼容模式复跑。r3自测已备案12/13的同一细标签差异不要求修改旧目录；说明判罚不变。

新代通过 owning 评分入口覆盖至少这些成对场景：

1. 同题新响应不继承旧人工FAIL；未审核是PENDING；绑定的新正确人工记录可PASS。
2. 人工PASS不能救已证实错出处/错值/缺项；正确真实引用仍通过，非全拒。
3. 人工记录绑错round/runtime/response SHA拒绝；第二轮不借第一轮裁决。
4. 运行manifest/gold/锚/pre-post错或解析异常：诊断落盘、非零、无裁决；完整新代正例可评分。
5. HTTP200后partial实发为1、HTTP前skip为0、未知无凭证不伪判。
6. 明确零discovery+正确枚举仍recall0；缺映射pending，完整组合键正例可用，外workspace不混源。
7. 多轮目录只读且结果分别落新目录，反例预期只用于事后判定；既有分母/决定性失败/掩码规则不变。

测试适配器不得读取gold生成答案。必要的评分专项和35冻结即可，生产源未改不重复526全套，不通过就定位同一接缝，不进行大重写。
